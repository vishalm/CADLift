## What it does

| Input | What you get |
|---|---|
| **PDF floor plan** (vector) | A navigable 3D model: walls, furniture blocks and floor slab. Fly through it with WASD in the browser. |
| **DXF / DWG** | Extruded 3D building or part, exported as GLB, STEP, DXF and STL. |
| **Image** (photo, sketch, blueprint) | 3D model via contour tracing or AI blueprint analysis (Azure OpenAI). |
| **Text prompt** | Parametric CAD model generated by an LLM (Azure OpenAI). |
| **Any 3D result** | Photoreal images, orbit videos and construction timelapses of any view (Azure OpenAI or FAL). |

Every result opens in the built-in 3D viewer and can be downloaded.

## Quick start (5 minutes)

### 1. Prerequisites

| Tool | Version | Check |
|---|---|---|
| Python | 3.11 or newer | `python3 --version` |
| Node.js | 20 or newer | `node --version` |
| Git | any | `git --version` |

### 2. Clone

```bash
git clone git@github.com:vishalm/CADLift.git
cd CADLift
```

### 3. Start the backend (terminal 1)

```bash
cd backend
python3 -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -e ".[dev]"
cp .env.example .env               # then edit .env (see "Configuration" below)
uvicorn app.main:app --reload --port 8000
```

The database tables are created automatically on first start. Check it is up:
[http://localhost:8000/health](http://localhost:8000/health) should return `{"status": "ok", ...}`.

### 4. Start the frontend (terminal 2, from the repo root)

```bash
npm install
npm run dev
```

### 5. Open the app

1. Go to [http://localhost:3000](http://localhost:3000)
2. Click **Sign up** ([/signup](http://localhost:3000/signup)) and create an account. There is no default user.
3. Upload a file from the dashboard.

That is it. AI features stay off until you add Azure OpenAI credentials (next section); everything else works without them.

## Configuration

All backend settings live in `backend/.env` (copy from [`backend/.env.example`](backend/.env.example)). The frontend works with no config; it calls `http://localhost:8000` by default.

### Required for production

| Variable | Default | Notes |
|---|---|---|
| `JWT_SECRET_KEY` | `change-me...` | **Change before deploying.** Any long random string. |
| `DATABASE_URL` | `sqlite+aiosqlite:///./cadlift.db` | Use `postgresql+asyncpg://...` in production. |
| `CORS_ORIGINS` | `*` | Comma-separated list of allowed frontend URLs in production. |

### Azure OpenAI (optional, enables AI features)

Needed for prompt-to-3D and AI blueprint analysis of images.

| Variable | Example | Notes |
|---|---|---|
| `LLM_PROVIDER` | `azure` | `none` turns AI off. |
| `AZURE_OPENAI_ENDPOINT` | `https://<resource>.openai.azure.com` | From Azure portal > your resource > Keys and Endpoint. |
| `AZURE_OPENAI_API_KEY` | | Same page. Never commit it. |
| `AZURE_OPENAI_API_VERSION` | `2025-04-01-preview` | |
| `AZURE_DEPLOYMENT_NAME` | `gpt-5-mini` | The deployment name you created in Azure AI Foundry. |
| `AZURE_VISION_DEPLOYMENT_NAME` | | Optional. Defaults to `AZURE_DEPLOYMENT_NAME` (must support images). |
| `AZURE_IMAGE_DEPLOYMENT_NAME` | `gpt-image-1` | Optional. Enables text-to-image for the AI mesh path and render studio photos. |
| `LLM_TIMEOUT_SECONDS` | `60` | Reasoning models can be slow; keep at 60 or more. |

Quick test that your Azure settings work (from `backend/` with the venv active):

```bash
python -c "import asyncio; from app.services.llm import llm_service as s; print(s.enabled); print(asyncio.run(s.generate_instructions('a coffee mug 90mm tall')))"
```

### Render studio (optional: Azure OpenAI or FAL)

Turns the current 3D view into a photoreal image, a short orbit video, or a construction
timelapse (empty site to finished building). Open a model, click **Render studio**, frame the
shot, pick an output and lighting, and click **Render current view**. Results appear in the panel
with download links.

Photos and videos each pick a provider on their own: Azure OpenAI when its deployment is set,
otherwise FAL (the same models image-blaster uses). So Azure photos plus FAL videos also works.

| Variable | Default | Notes |
|---|---|---|
| `AZURE_IMAGE_DEPLOYMENT_NAME` | | Azure `gpt-image-1` deployment for photos (uses the `AZURE_OPENAI_*` endpoint and key). |
| `AZURE_VIDEO_DEPLOYMENT_NAME` | | Azure Sora 2 deployment (e.g. `sora-2`) for videos. Sora takes a first frame only, so on Azure the timelapse starts from the site image but its last frame is not pinned to your render. |
| `FAL_KEY` | | From [fal.ai](https://fal.ai). Used for any step whose Azure deployment is empty. Never commit it. |
| `FAL_IMAGE_ENDPOINT` | `fal-ai/nano-banana-2/edit` | FAL image edit model. |
| `FAL_VIDEO_ENDPOINT` | `fal-ai/kling-video/v2.5-turbo/pro/image-to-video` | Must accept `image_url` and `tail_image_url` (first and last frame). |
| `RENDER_PROVIDER` | `auto` | `auto` (Azure first, then FAL), `azure`, or `fal`. |
| `RENDER_TIMEOUT_SECONDS` | `900` | Videos usually take 2 to 6 minutes. |

Renders are paid calls; at most two run at once per model. The studio returns 503 when no photo
provider is configured, and video outputs return 503 when no video provider is.

Create `.env` in the repo root only if your backend is not on port 8000:


Restart `npm run dev` after changing it.

## Using the app

### PDF floor plan to navigable 3D

1. Dashboard > CAD upload > drop a **vector** PDF (exported from AutoCAD/Revit, not a scan).
2. Optional: fill **Plan Width (m)** with the real width of the drawn floor plate. Left empty, the scale is estimated from 3.5' x 2' workstation symbols (falls back to 1:100).
3. Convert, then open the 3D viewer.

How the conversion works:
- Only the first page is read. The title block is cropped out automatically.
- Lines longer than 2 m become 3 m walls, shorter lines become 0.75 m furniture, filled shapes (columns) become solids, and a floor slab is added.
- Shapes under 150 mm (hatching, text fragments) are skipped.
- Output is a GLB (no STEP for PDFs: too many shapes for solid modelling).

### Colour and edit the model with AI chat

PDF plan models keep the drawing's colours, grouped into layers by kind and colour (for example *Furniture · green (#55aa00)*). Open the 3D viewer and use the **Edit with AI** panel on the right (needs Azure OpenAI):

- "Make all furniture warm oak wood and the floor dark grey concrete"
- "The green furniture is plants: make it 1.2m tall and leaf green"
- "Hide the red solids", "Walls off-white and 2.8m tall", "Lines are too thick, use 60mm"

Each change rebuilds the model (about 10 seconds) and is saved as a version; **Undo** steps back. Chat changes whole layers (colour, height, visibility, name) plus scale and line thickness; it does not move or add individual objects. The **Layers** list in the panel shows every layer name you can refer to.

API: `POST /api/v1/jobs/{id}/chat` with `{"message": "..."}`, and `POST /api/v1/jobs/{id}/chat/undo`.

## API

Interactive docs: [http://localhost:8000/docs](http://localhost:8000/docs). All job endpoints need a bearer token.

```bash
# 1. Sign up once (or use the UI)
curl -X POST http://localhost:8000/api/v1/auth/register \
  -H "Content-Type: application/json" \
  -d '{"email":"me@example.com","password":"choose-a-password","display_name":"Me"}'

# 2. Log in and keep the token
TOKEN=$(curl -s -X POST http://localhost:8000/api/v1/auth/login \
  -H "Content-Type: application/json" \
  -d '{"email":"me@example.com","password":"choose-a-password"}' \
  | python3 -c "import sys,json; print(json.load(sys.stdin)['access_token'])")

# 3a. PDF floor plan -> navigable GLB
curl -X POST http://localhost:8000/api/v1/jobs -H "Authorization: Bearer $TOKEN" \
  -F job_type=cad -F mode=floor_plan \
  -F 'params={"extrude_height": 3000, "plan_width_m": 100}' \
  -F "upload=@plan.pdf;type=application/pdf"

# 3b. DXF / DWG -> 3D
curl -X POST http://localhost:8000/api/v1/jobs -H "Authorization: Bearer $TOKEN" \
  -F job_type=cad -F mode=floor_plan \
  -F 'params={"extrude_height": 3000}' \
  -F "upload=@building.dxf"

# 3c. Text prompt -> 3D (needs Azure OpenAI)
curl -X POST http://localhost:8000/api/v1/jobs -H "Authorization: Bearer $TOKEN" \
  -F job_type=prompt -F mode=prompt_to_3d \
  -F 'params={"prompt": "a coffee mug 90mm tall"}'

# 4. Poll the job, then download outputs by file id
curl -H "Authorization: Bearer $TOKEN" http://localhost:8000/api/v1/jobs/<job_id>
curl -o model.glb http://localhost:8000/api/v1/files/<glb_file_id>
```

Job params of note: `extrude_height` (mm), `wall_thickness` (mm), `plan_width_m` (PDF only, 1-5000), `furniture_height` (mm, PDF only).

## Troubleshooting

| Problem | Fix |
|---|---|
| `[Errno 48] Address already in use` | Something else is on port 8000. Find it with `lsof -nP -iTCP:8000 -sTCP:LISTEN`, stop it, or run on another port and set `VITE_API_BASE_URL`. |
| `sh: vite: command not found` | Run `npm install` in the repo root first. |
| `GEO_STEP_GENERATION_FAILED` ... `cadquery is not installed` | `pip install -e .` again inside `backend/.venv` (cadquery is a required dependency). |
| `No available triangulation engine!` | `pip install mapbox-earcut` (included in `pip install -e .`). |
| PDF upload gives `No vector geometry found` | The PDF is a scan. Export a vector PDF from your CAD tool. |
| PDF model is the wrong size | Set **Plan Width (m)** to the real floor plate width. |
| `401 Unauthorized` / "Invalid credentials" | Log in again; there is no default account, sign up first. |
| AI features do nothing | Check `LLM_PROVIDER=azure` and the four `AZURE_*` variables, then restart the backend. |
| DWG upload fails | Install the [ODA File Converter](https://www.opendesign.com/guestfiles/oda_file_converter), or save as DXF. |

Backend logs print in the `uvicorn` terminal; each failed job logs an `error_code` and details.

```
├── backend/

└── render.yaml              # Render.com deployment
```

### How a job flows

```
Upload (UI or API) -> POST /api/v1/jobs -> file validated and stored
  -> pipeline by type: cad (.dxf/.dwg/.pdf) | image | prompt
  -> outputs saved (GLB / STEP / DXF / STL) and linked to the job
  -> UI polls the job, then opens the GLB in the viewer
```

## Deployment

- **Docker:** `docker build -t cadlift-backend . && docker run -p 8000:8000 --env-file backend/.env cadlift-backend`
- **Render.com:** [`render.yaml`](render.yaml) defines the backend and frontend services. Set `AZURE_OPENAI_ENDPOINT` and `AZURE_OPENAI_API_KEY` in the Render dashboard. Step-by-step guide: [DEPLOYMENT.md](DEPLOYMENT.md).

Before going live: change `JWT_SECRET_KEY`, restrict `CORS_ORIGINS`, and use PostgreSQL.
